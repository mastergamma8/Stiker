# TGS Logo Bot

Telegram-бот для анимированных стикеров и премиум-эмодзи (`.tgs`), с тремя
возможностями:

1. **Публичный каталог-магазин** — `/start` открывает витрину готовых
   стикеров и премиум-эмодзи; любой пользователь смотрит каталог, собирает
   свой пак или покупает один дизайн, платит Telegram Stars и получает
   стикер-пак + эмодзи-пак со своим текстом. Подробности — раздел
   [«Каталог»](#каталог-магазин-стикеров-и-премиум-эмодзи) ниже.
2. **Меняет текст** на стикере/эмодзи, если этот текст сделан векторными
   фигурами (а не картинкой) — ручной режим для своих файлов, **только для
   админа** (см. `TGS_BOT_ADMIN_IDS`): без этого ограничения кто угодно мог
   бы получить персонализированный файл в обход платного каталога.
3. **Собирает из готовых стикеров свой пак премиум-эмодзи** (только для
   админа, см. `TGS_BOT_ADMIN_IDS`) — присылаете стикеры один за другим,
   бот создаёт и пополняет кастомный emoji-набор через Bot API (это же
   используется и внутри каталога-магазина).

Бот сам находит нужную группу по геометрии фигур — не по имени слоя. Это
важно, потому что почти во всех реальных `.tgs`-файлах (чужие стикеры,
премиум-эмодзи) слои и группы вообще никак не называются — Bodymovin/After
Effects при экспорте оставляет `nm` пустым, и в JSON это выглядит как
`None`. Имя `mylogo` из исходного `AnimatedSticker.tgs` было исключением,
а не правилом, так что теперь оно не требуется: бот раскладывает файл на
все векторные группы и оценивает каждую по тому, насколько она похожа на
текст (см. «Как бот находит текст» ниже). Ручной выбор через `/target`
остался — как подстраховка, если авто-выбор ошибся, или если в стикере
несколько надписей и нужна конкретная.

## Как это работает

1. Пользователь присылает `.tgs` файл, пересылает анимированный стикер,
   присылает премиум-эмодзи отдельным сообщением или просто печатает его
   в тексте.
2. Бот распаковывает gzip → Lottie JSON и ищет среди всех векторных групп
   (по всем слоям, по всем precomp-ассетам, включая вложенные группы) ту,
   что больше всего похожа на текст.
3. Бот показывает, что нашёл (примерный размер и число контуров), и
   спрашивает новый текст.
4. Текст отрисовывается шрифтом **Poppins Bold** (кириллица подхватывается
   шрифтом **DejaVu Sans Bold**, если в тексте встречаются русские буквы) и
   превращается в такие же bezier-контуры ("sh"-пути), какие использует
   Lottie/TGS.
5. Новые контуры вставляются на место старых **внутри той же группы** — сам
   fill (заливка), transform (позиция/поворот/масштаб) и вся остальная
   анимация стикера не трогаются вообще. Меняются только сами буквы.
6. Готовый файл сжимается обратно в gzip и отправляется пользователю
   (документом и — если Telegram примет файл как стикер — сразу превью
   стикером).

Движок (`tgs_editor.py` + `text_to_lottie.py`) не зависит от Telegram и
проверен отдельно на `demo_cli.py` — см. папку `examples/`.

## Как бот находит текст

Для каждой векторной группы с двумя и более отдельными "единицами формы"
бот считает несколько геометрических признаков и складывает их в один
балл — побеждает группа с максимальным баллом. Такой "единицей" может быть
как путь (`sh`), лежащий прямо в группе, так и вложенная подгруппа (`gr`) —
это важно, потому что реальные файлы хранят слово по-разному: иногда все
буквы — это несколько путей-соседей в одной группе, а иногда каждая буква —
своя отдельная подгруппа со своим смещением по X (так текст раскладывают
многие инструменты, чтобы у каждой буквы был свой кернинг). Если считать
только прямые дочерние пути, автовыбор находит не всё слово, а лишь
отдельную многоконтурную букву внутри него (например, только "e" — у неё
два контура: внешний и "дырка"); учёт вложенных подгрупп как таких же
единиц — то, что позволяет увидеть слово целиком.

- **Буквы стоят на одной строке.** Центры отдельных единиц группы сильно
  разнесены по горизонтали и почти не расходятся по вертикали — это самый
  сильный признак (у настоящего текста это отношение в 10-25 раз выше, чем
  у иконок и фоновых фигур).
- **Группа шире, чем выше.** Строка текста почти всегда заметно шире своей
  высоты.
- **Правдоподобный масштаб.** Высота отдельных букв — разумная доля от
  холста (не на весь кадр, как персонаж/фон, и не на пиксель, как мелкая
  декоративная деталь).
- **Разумное число единиц** (буквы + внутренние "дырки" типа о/е/а/g).
- Небольшие бонусы: путь статичный (не покадрово анимированный — буквы
  почти никогда не "плывут" по контуру, в отличие от прочей мультипликации
  стикера), заливка сплошная (не градиент), у группы/слоя/ассета вообще
  есть хоть какое-то имя.

Ни один признак сам по себе не доказателен, но вместе они уверенно отделяют
текст от персонажей, фона и декоративных иконок — проверено на реальном
многослойном стикере без единого имени слоя.

## Установка

Нужен Python 3.10+.

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Токен бота

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram → `/newbot` →
   получите токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.
2. Скопируйте `.env.example` в `.env` и впишите токен:
   ```bash
   cp .env.example .env
   ```
   ```
   TGS_BOT_TOKEN=123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
   (или экспортируйте переменную окружения `TGS_BOT_TOKEN` любым другим
   способом).

   ⚠️ **Если этот проект вам достался с уже вписанным в `bot.py` токеном**
   (было раньше, как запасной вариант, чтобы бот заработал совсем без
   настройки) — этот токен больше не секрет, потому что физически лежит в
   файле. Выпустите новый через `@BotFather` → `/mybots` → ваш бот → `API
   Token` → `Revoke current token`, и впишите новый в `.env` как выше.

3. По умолчанию в коде уже вписан один админ-ID (см. `ADMIN_IDS` в
   начале `shop.py`) — если это ваш `/myid`, ничего делать не нужно.
   Чтобы сменить или добавить админов без правки кода — впишите ID через
   запятую в `TGS_BOT_ADMIN_IDS` в `.env`, это переопределяет значение по
   умолчанию.

## Запуск

```bash
python bot.py
```

Бот запускается через long polling — держите процесс запущенным (на своей
машине, в screen/tmux, systemd-сервисе или на любом VPS с доступом в
интернет). Я не могу запустить его за вас — в моей среде выполнения нет
сетевого доступа к Telegram, так что живьём бот здесь не тестировался, но
весь движок замены текста (включая авто-поиск группы) — и логика самого
бота вокруг него — прогнаны прямо здесь на вашем `AnimatedSticker.tgs` и на
исходных примерах.

### Команды бота

Для обычных пользователей:

- `/start` — каталог-магазин (см. ниже); первому сообщению всегда отвечает
  он, независимо от того, в каком режиме бот использовался раньше.
- `/myid` — узнать свой Telegram ID.

Ручной режим (правка текста на присланном файле) и сборка своего пака —
**только для админа** (см. `TGS_BOT_ADMIN_IDS`): без этого ограничения
кто угодно мог бы получить персонализированный стикер в обход платного
каталога. Обычным пользователям на файл/стикер/эмодзи, `/target` или
`/newpack` бот ответит, что это доступно только администратору, и
предложит `/start`.

Команды администратора (в дополнение к каталожным — см.
[«Админ-команды»](#админ-команды) ниже):

- `/target <номер>` или `/target <имя>` — выбрать конкретную надпись
  вручную (номер бот показывает при получении файла), если авто-выбор
  ошибся или в стикере несколько надписей. Если файл уже загружен в
  диалоге, выбор применяется сразу же, без повторной отправки файла.
- `/target` без аргумента — сбросить ручной выбор, снова искать
  автоматически.
- `/newpack [название]` — начать сборку пака премиум-эмодзи (см. ниже).
- `/donepack` — закончить сборку пака, получить ссылку `t.me/addemoji/...`.
- `/cancelpack` — отменить сборку пака; если набор уже создан в Telegram,
  бот его удалит (`deleteStickerSet`), чтобы не оставался пустой мусор.
- `/cancel` — отменить текущее редактирование текста **или** сборку пака
  (эквивалент `/cancelpack`, если пак сейчас в работе).

### Премиум-эмодзи

Работают так же, как стикеры — можно прислать премиум-эмодзи отдельным
сообщением или просто напечатать его прямо в тексте, бот сам достанёт файл
через Bot API (`getCustomEmojiStickers`). Технически это тот же формат, что
и обычный анимированный стикер: тот же `.tgs` (gzip + Lottie JSON), тот же
холст 512×512, тот же лимит 64 КБ — Telegram использует отдельный формат
100×100 только для *статичных/видео* кастомных эмодзи, не для
анимированных, так что движку не нужно ничего знать про эту разницу.

## Сборка пака премиум-эмодзи (`/newpack`)

**Только для админа** (см. `TGS_BOT_ADMIN_IDS`) — обычным пользователям эта
команда недоступна, чтобы не обходить платный каталог: без ограничения
кто угодно мог бы собрать точно такой же персональный пак бесплатно.

1. `/newpack Название пака` (без названия — бот спросит отдельным
   сообщением).
2. Присылайте анимированные стикеры один за другим — форвардите их из
   любого готового стикерпака, присылайте премиум-эмодзи, или используйте
   то, что сами отредактировали через текстовый режим бота выше. Каждый
   становится отдельным кастомным эмодзи в наборе.
   - Эмодзи для поиска (`emoji_list`) бот берёт из самого стикера
     (`message.sticker.emoji` — оно уже есть у любого стикера из готового
     пака), иначе — из подписи к файлу, если в ней есть эмодзи, иначе
     ставит один нейтральный по умолчанию.
   - Первый стикер создаёт набор (`createNewStickerSet`,
     `sticker_type=custom_emoji`), остальные добавляются в него
     (`addStickerToSet`).
3. `/donepack` — бот присылает ссылку `https://t.me/addemoji/<имя_набора>`
   для добавления пака себе.

Техническое имя набора (`name`, то, что видно в ссылке) генерируется
автоматически из названия — кириллица транслитерируется, всё лишнее
убирается, добавляется ID пользователя, а при конфликте (имя уже занято —
короткие имена уникальны для всего Telegram, не только для этого бота)
бот сам перегенерирует имя с другим суффиксом и повторит попытку (см.
`pack_builder.py::generate_set_name`, `sticker_sets.py::create_set_with_retry`).

**Важно:** видеть кастомные эмодзи может кто угодно, а вот отправлять их в
сообщениях со своего аккаунта — только пользователи с Telegram Premium.
Это ограничение самого Telegram, не бота.

## Каталог (магазин стикеров и премиум-эмодзи)

`/start` теперь открывает не справку, а витрину: список готовых дизайнов,
каждый из которых можно купить отдельно или собрать несколько в свой пак —
оплата в Telegram Stars (`XTR`), без банковских карт и юрлица.

### Как каталог наполняется (админ)

1. Администратор (см. `TGS_BOT_ADMIN_IDS` выше) присылает боту **любой
   стикер из готового стикер-пака** — пересылает существующий стикер, или
   команда `/importpack [название]`, после которой бот попросит стикер.
2. Бот через `getStickerSet` забирает **весь** исходный пак и для каждого
   анимированного (`.tgs`) стикера:
   - скачивает оригинал и сохраняет как есть;
   - тем же движком (`tgs_editor.replace_text`), что и в ручном режиме,
     впечатывает текст-плейсхолдер (по умолчанию **TEXT**, см.
     `TGS_BOT_PLACEHOLDER_TEXT`) — это демо-версия для каталога;
   - запоминает, какую именно группу нашёл движок, чтобы позже подставить
     туда текст покупателя без повторного поиска.
   - стикеры без PNG/WEBM (не анимированные) и уже импортированные раньше
     — пропускаются, итог виден в ответе бота.
3. Бот собирает демо-стикеры в два обычных Telegram-набора с названием
   плейсхолдера (по умолчанию **«TEXT»**) — стикерпак и отдельно пак
   премиум-эмодзи — и присылает на них ссылки. Это и есть витрина: тот же
   `t.me/addstickers/...`/`t.me/addemoji/...`, которые видит пользователь,
   листая каталог внутри бота.
4. Бот спрашивает цену за один дизайн в Stars — она применяется ко всем
   позициям без цены. С этого момента каталог открыт всем через `/start`.

Повторный `/importpack` (другой исходный пак) **дополняет** тот же каталог
и те же два витринных набора, а не создаёт всё заново.

### Как это выглядит для покупателя

- `/start` → «🛍 Каталог» — карточка дизайна (сам анимированный стикер) с
  кнопками: пролистать ◀️▶️, добавить в свой пак, купить только этот, открыть
  корзину.
- «➕ Добавить в свой пак» несколько раз → «🛒 Мой пак» → «⚡ Купить пак» —
  это и есть «собрать пак, выбирая нужные стикеры».
- После выбора бот спрашивает текст (до 40 символов, кириллица и латиница),
  сразу присылает превью первого дизайна с этим текстом и выставляет счёт в
  Stars.
- После оплаты бот на лету генерирует персональные версии всех выбранных
  дизайнов (тем же движком, с тем же исходником и той же найденной группой,
  что и на этапе импорта — только текст другой) и создаёт **лично для
  покупателя** новый стикер-пак и эмодзи-пак с этим текстом, плюс присылает
  каждый файл отдельно документом.
- Если оплата прошла, а собрать паки не получилось — бот сам возвращает
  Stars через `refundStarPayment` и не оставляет покупателя без ответа.

### Админ-команды

- `/importpack [название]` — импортировать стикер-пак в каталог (см. выше).
- `/catalog` — пролистать каталог **реальными стикерами** (◀️▶️, как у
  покупателя), с ценой/id/статусом под каждым и кнопкой **🗑 Удалить**:
  после подтверждения позиция пропадает не только из каталога, но и из
  обоих витринных Telegram-паков (`deleteStickerFromSet`) — это
  необратимо, в отличие от `/removeitem` ниже.
- `/setprice <id|all> <звёзды>` — задать цену одной позиции или всем сразу.
- `/removeitem <id>` / `/restoreitem <id>` — скрыть/вернуть позицию в
  публичном каталоге без удаления из витринных паков (сам дизайн,
  оригинал и стикер в витрине остаются на месте — на случай, если нужно
  спрятать позицию временно, а не насовсем).
- `/rebuildpacks` — дособрать витринные паки по каталогу вручную. Обычно
  не нужна — `/importpack` уже делает это сам, — но пригодится, если
  импорт прервался (например, бот перезапустился или Telegram на время
  ограничил частоту запросов, см. ниже) и нужно просто дособрать
  недостающее без повторной загрузки исходного пака.
- `/newpack` / `/donepack` / `/cancelpack` — сборка собственного пака из
  готовых стикеров (см. [«Сборка пака премиум-эмодзи»](#сборка-пака-премиум-эмодзи-newpack)
  выше) — доступно только админу.
- `/freeusers` — список пользователей с бесплатным доступом к каталогу.
- `/revokefree <id>` — забрать у пользователя бесплатный доступ.
- `/stats` — число оплаченных/доставленных/бесплатных заказов и выручка.

**Про ограничение Telegram на скорость создания стикеров:** `createNewStickerSet`/
`addStickerToSet` Telegram ограничивает заметно жёстче, чем обычные
сообщения — импорт паузит между запросами и сам дожидается точно
столько, сколько попросит Telegram, если лимит всё же превышен (вместо
падения с ошибкой), сообщая об этом в чат, если ожидание больше
нескольких секунд. Импорт большого пака (десятки стикеров) поэтому может
занять несколько минут — это нормально, просто ждите; прогресс каждый
раз сохраняется, так что даже если что-то прервётся на середине,
`/importpack` или `/rebuildpacks` продолжат с того же места, а не начнут
заново.

### Хранилище

Каталог, корзины и заказы живут в SQLite (`db.py`, файл `bot.db` рядом с
`bot.py` — путь настраивается через `TGS_BOT_DB_PATH`), а не в памяти
процесса — в отличие от сессий редактирования текста и сборки пака (см.
«Известные ограничения»), заказы должны переживать перезапуск бота, потому
что между «выставили счёт» и «Stars списались» может пройти сколько
угодно времени.

```
.env.example     — шаблон переменных окружения
```

## Быстрая проверка движка без Telegram

```bash
python demo_cli.py AnimatedSticker.tgs "Новый текст" output.tgs
python demo_cli.py AnimatedSticker.tgs "Привет" output_ru.tgs

# если авто-выбор нашёл не ту группу — номер или имя пятым аргументом:
python demo_cli.py other_sticker.tgs "Новый текст" output.tgs 2
```

Появится `output.tgs` — откройте его тем же способом, каким обычно
просматриваете стикеры (например, через `@BotFather` → `/newsticker`, или
любым просмотрщиком Lottie/TGS).

## Известные ограничения

- **Лимит Telegram 64 КБ на .tgs** — бот проверяет размер готового файла и
  откажется отправить файл, если текст слишком длинный.
- **Работает с одной надписью за проход** — если в стикере несколько
  текстовых групп, автоматически возьмётся та, что набрала больше очков
  (обычно самая заметная надпись); остальные видно в списке кандидатов и
  можно выбрать через `/target <номер>`.
- **Геометрический поиск — эвристика, не гарантия.** На нестандартных
  макетах (текст в столбик, повёрнутый на 90°, состоящий всего из одной
  буквы, или стикер с несколькими одинаково заметными надписями) авто-выбор
  может промахнуться — тогда бот покажет список кандидатов, и нужный
  берётся через `/target`.
- **Символы не из Poppins/DejaVu** (например, CJK, эмодзи) — тихо
  пропускаются. Если нужна поддержка других алфавитов — можно добавить ещё
  один шрифт-fallback в `tgs_editor.py` (`DEFAULT_FALLBACK_FONT`) или
  передать свой `.ttf` в `fonts/`.
- Шрифт для замены — не точная копия исходных геометрических фигур (это
  была бы отдельная, гораздо более сложная задача — генерировать фигуры "в
  стиле" рукотворного логотипа под произвольный текст), а чистая
  векторная типографика, стилистически близкая (жирный геометричный
  гротеск). Сравните `examples/demo_MyLogo.tgs` с оригиналом — если стиль
  не устраивает, шрифт легко заменить: положите свой `.ttf` в `fonts/` и
  поменяйте путь в `DEFAULT_PRIMARY_FONT` (см. `tgs_editor.py`).
- **Сборка пака поддерживает только анимированные `.tgs`-стикеры** (не
  статичные PNG/WEBP и не видео WEBM) — сознательное ограничение объёма,
  весь остальной бот тоже только про `.tgs`.
- **Сессия пака живёт в памяти процесса** (та же `MemoryStorage`, что и у
  редактирования текста) и заканчивается вместе с `/donepack`,
  `/cancelpack` или перезапуском бота. Сам набор при этом никуда не
  девается — он на серверах Telegram, — но чтобы дополнить его *позже*, в
  новой сессии после `/donepack`, понадобится либо запомнить `name` набора
  самому и дописать простую команду вида `/addtopack <name>`, либо
  расширять `bot.py` под постоянное хранилище (сейчас его нет и не было —
  тот же характер ограничения, что и у сессий редактирования текста).
- **200 эмодзи на набор** — лимит самого Telegram для `custom_emoji`
  паков; `addStickerToSet` вернёт ошибку при попытке добавить сверх него,
  бот покажет её текстом и предложит `/donepack`.
- **Лимиты Telegram на витринные и покупательские наборы** — анимированный
  обычный стикер-пак ограничен 50 стикерами, `custom_emoji`-пак — 200. Если
  исходный пак больше 50 позиций, витринный стикер-пак (`t.me/addstickers`)
  покажет только первые 50 — остальные всё равно в каталоге и продаются,
  просто не входят в этот конкретный предпросмотр-набор; на покупку это не
  влияет, если только кто-то не соберёт пак больше 50 стикеров или 200
  эмодзи разом (тогда лишнее в этом одном заказе будет пропущено — см.
  `sticker_sets.build_or_extend_set`).
- **`/catalog`'s 🗑 Удалить опирается на `showcase_sticker_file_id`/
  `showcase_emoji_file_id`** (по позиции каталога — какой именно стикер/эмодзи
  внутри витринных паков ей соответствует, чтобы звать `deleteStickerFromSet`
  адресно). Для позиций, импортированных **до** появления этих двух колонок,
  бот сам восстанавливает их при первом `/catalog` или `/importpack` после
  обновления (`shop._backfill_showcase_file_ids`) — эвристикой по порядку
  позиций, в предположении, что паки только пополнялись (`/removeitem` их не
  трогает) и ни один `/importpack` не запускался между скрытием старой
  позиции и этим восстановлением. В обычном использовании (импорт(ы), потом
  изредка что-то скрывают) это всегда верно; при более экзотической истории
  импортов/скрытий вперемешку сверьте пару позиций с реальным паком в
  Telegram, прежде чем полагаться на массовое удаление.
- **Одна цена на дизайн**, не отдельно на «как стикер» / «как эмодзи» —
  покупатель всегда получает и то, и другое за одну цену. Если нужна
  раздельная цена — тип поставки (`orders.delivery_format`) уже заложен в
  базе, доработка небольшая (сейчас захардкожено как «оба»).
- **Текст один на весь заказ** — если в корзине несколько дизайнов, все
  выходят с одним и тем же текстом покупателя за один проход оформления;
  чтобы получить разные тексты на разных дизайнах, сейчас нужно оформить
  несколько отдельных заказов.
- **SQLite открывается заново на каждый запрос** (`db.py::_connect`) — для
  личного/небольшого бота этого достаточно и проще в поддержке, чем пул
  соединений; при действительно высокой нагрузке это первое место для
  оптимизации.
- **Генерация текста — синхронная (CPU-bound) операция** внутри
  async-обработчика, как и в ручном режиме редактирования — для одного
  стикера это доли секунды, но при очень большом паке (десятки позиций,
  оформленных одним заказом) бот на это время перестаёт отвечать другим
  пользователям. Обычный размер каталога/заказа эту границу не заденет.

## Структура проекта

```
bot.py                 — Telegram-бот (aiogram 3): редактирование текста + /newpack
db.py                  — каталог/корзины/заказы/настройки магазина (SQLite)
sticker_sets.py        — создание/пополнение Telegram-наборов (общее для /newpack и каталога)
shop.py                — каталог-магазин: /start, витрина, корзина, оплата Stars, админ-команды
tgs_editor.py          — авто-поиск текстовой группы + вставка новых путей + gzip упаковка
text_to_lottie.py      — шрифт → векторные bezier-контуры в формате Lottie
pack_builder.py        — генерация короткого имени набора эмодзи + подбор emoji_list (без aiogram)
demo_cli.py            — проверка движка из командной строки, без Telegram
.env.example           — шаблон переменных окружения (токен, админы, и т.д.)
fonts/                 — Poppins-Bold.ttf (OFL) и DejaVuSans-Bold.ttf (бесплатная лицензия)
examples/               — готовые примеры на основе вашего файла
```
